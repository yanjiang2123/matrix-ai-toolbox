My internship project · Local-first data workflow

我把日常 SQL 排查与数据核对，做成了一个本地工作台。

这个项目来自我实习时遇到的真实问题：数据库查询、表数据量统计、SQL 排查、Excel 核对和格式转换分散在不同操作里。我把这些高频流程整合成了一个可在本机运行、可独立演示的数据工具。

What I implemented

这些是我已经实现并验证过的核心能力。

我围绕查询、排查、核对和转换四类工作任务组织功能，让使用者可以在同一个本地页面内完成操作。

01

数据库查询与统计

我通过 Java/JDBC 加载目标数据库驱动，支持在运行时填写连接信息、执行只读 SQL，并遍历数据库表、统计表行数。

JDBC只读检查表行数统计
02

SQL 拆分与 AI 排查

我实现了多语句 SQL 拆分和静态差异分析，先提取 JOIN、过滤条件与字段等证据，再调用兼容模型接口补充语义影响和验证建议。

SQL Parser证据链AI 建议
03

数据库与文件核对

我把数据库结果、单表数据和 Excel/CSV 文件的比较整合进工具，可按主键定位新增、缺失以及字段内容不一致的数据。

结果集对比Excel / CSV差异定位
04

结构化转换

我实现了 Excel 转 INSERT SQL、PDF、Word，以及结构化文本转 Excel；图片识别结果也可以整理为 Excel，但当前 OCR 依赖 macOS Vision。

openpyxl文档导出OCR

How I made it safe

我公开的是项目能力，不是公司的数据。

为了把项目作为作品展示，我移除了公司环境、真实连接、账号密码、商业数据库驱动、测试数据和运行产物。公开仓库只保留通用实现和空白配置示例。

✓

运行时连接

我把数据库连接改成前端运行时配置，连接信息只保存在本机当前进程中，不写回项目配置文件。

✓

密钥不入库

AI 接口地址、模型和密钥由使用者运行时填写；公开网站与源码不包含公司账号、内部地址或密钥。

✓

人工确认执行

我让 AI 只负责生成分析和验证 SQL。建议必须通过本地只读检查，并由使用者确认后手动执行。

What I would improve next

我也会主动说明项目目前的边界。

AI 能力需要使用者提供兼容接口、模型和密钥。未配置模型时，本地规则分析仍然可以工作；模型结论必须人工复核。

数据库适配需要使用者提供对应的 JDBC 驱动和可用 JDK。项目不包含商业驱动，大数据量比较仍需要继续完善分页和分片。

图片 OCR当前实现依赖 macOS Vision，Windows 版本尚未完成 OCR 适配，因此我不会把它描述成全平台完整能力。
