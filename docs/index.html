真实运行界面

先看证据，再解释影响。

最新版 SQL 排查工作台可在不连库时比较新老脚本，并直接指出可能导致丢数或倍乘的逻辑变化。

业务排查流程

不是字符串 diff，
是一条完整核对链路。

流程来自日常指标核对、报表迁移与数据链路追溯场景。每一步都给出下一步验证方向，而不是只展示文本变化。

  1. 01

    先统一范围与口径

    固定同一时间窗，核对 WHERE、机构、状态、维度和指标定义，避免把配置差异误判成数据问题。

  2. 02

    再比较结构与逻辑

    识别表源、字段映射、JOIN 类型与条件、过滤、分组和聚合粒度变化，并生成对应验证建议。

  3. 03

    从总量下钻到明细

    先比较字段和 COUNT，再按主键稳定对齐；单独识别重复键、额外行、仅 A、仅 B、NULL 与值差异。

  4. 04

    沿链路留存证据

    记录实际执行 SQL、参数、分片范围、结论和下一步；结果可导出，便于复核和继续追溯。

反“假绿”门禁

这些情况不会再被判成“完全一致”

  • 重复主键顺序变化、额外重复行与超大重复组分别处理
  • 字段结构变化重复表头、缺失字段、只有主键可比均会阻止假结论
  • 复合键与空值保留键边界，并区分 NULL、空字符串和字面量 NULL
  • 抽样与漏片抽样仅给阶段性判断；全量取数不完整时主动降级
结论可信度规则证据 + 数据完整性 + 人工确认

技术实现

页面负责编排，专业模块负责证据。

浏览器只访问本地 Flask 服务。数据库查询通过 Java/JDBC 执行；SQL、文件和转换逻辑由独立模块完成；外部模型是可选增强，不影响本地规则能力。

  • 敏感配置只保存在当前进程内存
  • 账号、密码与 SQL 不进入命令行参数
  • 写接口需要当前页面会话令牌

项目背景

从真实、重复的数据排查工作出发。

日常核对需要在数据库客户端、SQL 脚本和 Excel 文件之间反复切换。这个项目不试图重做数据库客户端，而是把高频排查动作和证据留存在同一条工作流里。

已知边界

  • 真实数据库验证需要目标 JDK、JDBC 驱动、网络与只读凭据；公开版本未连接生产库测试
  • AI 功能需要使用者提供兼容接口和模型配置，且不会自动执行生成 SQL
  • 图片 OCR 对低清、旋转或复杂合并单元格仍需人工核对
  • 极长 PDF 单元格为保证分页会按上限展示并明确告警
  • 旧版 .xls 需先另存为 .xlsx 后再进行文件比对
